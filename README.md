# 🔐 보안 핵심 시스템 분석: SHA-256 실전 관점

> **백엔드 & 보안 중심 리서치 프로젝트**  
> 암호학적 해시 함수, 데이터 무결성, 신뢰 최소화 시스템

---

## 🔹 이 프로젝트를 진행한 이유

현대의 백엔드 시스템은 다음과 같은 **신뢰 전제(trust assumptions)** 위에서 동작한다.

- 데이터는 **조용히 변경되면 안 된다**
- 요청은 **검증 가능해야 한다**
- 저장된 정보는 **위·변조에 강해야 한다**

이 프로젝트는 이러한 전제를 가능하게 만드는 핵심 기술 중 하나인  
**SHA-256** 해시 함수를 분석한다.

SHA-256은 다음과 같은 시스템의 기반을 이룬다.
- 블록체인 시스템 (예: Bitcoin)
- 디지털 서명 검증
- 백엔드 서비스의 파일 및 데이터 무결성 검증

목표는 SHA-256을 *“사용하는 것”*이 아니라,  
**왜 시스템이 이 알고리즘을 신뢰하는지**,  
그리고 **그 신뢰가 언제 깨질 수 있는지**를 이해하는 데 있다.

---

## 🔹 이 프로젝트가 보여주는 것

본 리서치는 다음과 같은 역량을 보여준다.

- 단순 API 사용이 아닌 **보안 보장(Security Guarantee)에 대한 사고**
- 암호학적 primitive를 **시스템 설계 관점**에서 분석
- 백엔드 보안 전제가 **알고리즘 수준에서 어떻게 성립되는지**에 대한 이해
- 이상적인 모델뿐 아니라 **현실적인 공격 벡터와 한계** 인식

---

## 🔹 기술적 분석 범위

- 암호학적 해시 함수의 기본 개념
- **SHA-256** 내부 구조 및 압축 라운드
- 충돌 저항성(Collision Resistance)
- 역상 저항성(Pre-image Resistance)
- 무작위 대입 공격과 연산 비용
- SHA-256의 실제 활용:
  - 블록체인 블록 연결 구조
  - 디지털 서명 파이프라인
  - 파일 체크섬 기반 무결성 검증
- 보안 한계 요소:
  - GPU / ASIC 기반 고속 연산 공격
  - 양자 컴퓨팅 위협 모델

---

## 🔹 시스템 관점에서 본 SHA-256

백엔드 엔지니어링 관점에서 SHA-256은 다음을 가능하게 한다.

- **불변(Immutable) 데이터 구조**  
  → 블록체인 형태의 append-only 로그

- **위·변조 탐지(Tamper Detection)**  
  → 원본 비교가 아닌 해시 비교

- **신뢰 최소화(Trust Minimization)**  
  → 중앙 기관에 의존하지 않는 검증

본 프로젝트는 암호 이론을  
**실제 백엔드 시스템 설계 결정과 연결**하는 데 초점을 둔다.

---

## ⚠️ 보안 트레이드오프와 현실적 제약

본 연구에서는 다음과 같은 현실적 문제도 다룬다.

- 보안 강도 vs 연산 비용
- 대규모 트래픽 환경에서의 확장성 문제
- SHA-256 단독 사용의 한계:
  - Salt 및 Key Stretching 미적용 시 위험
  - 프로토콜 설계 부재 시 보안 붕괴 가능성

이는 **“안전한 알고리즘”과 “안전한 시스템”이 다르다**는 점을 강조한다.

## 🔹 백엔드 & 보안 직무에서의 의미

이 프로젝트는 다음을 증명한다.
